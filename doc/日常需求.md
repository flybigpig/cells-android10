# Android Framework 日常开发需求列表（带工作量评估版）
> 适用：AOSP ROM / 设备厂商 Framework 开发；工作量说明：
> - S：小（0.5~2人天，简单改配置、加日志、单文件修改）
> - M：中（2~5人天，逻辑修改、新增简单接口、调试）
> - L：大（5~15人天，模块改造、多模块联动、兼容性验证）
> - XL：超大（>15人天，架构改动、大规模迁移、完整特性开发）
>
> 字段：序号 | 工作项 | 工作量 | 难度 | 风险点 | 交付物

## 1. 系统服务与 AMS/WMS 相关
|序号|工作项|工作量|难度|风险点|交付物|

## 附加汇总说明
1. **难度分级**
    - 低：配置修改、新增属性、selinux规则补全，代码改动很小
    - 中：单模块逻辑修改，接口新增，问题定位，有明确可复现场景
    - 高：多模块联动、锁/并发、跨进程、SystemUI/WMS/AMS核心模块
2. **风险共性**
    - Framework改动最容易踩坑：**兼容性回归、OTA升级、CTS/GTS、并发死锁**；核心服务（AMS/WMS/PMS）任何改动都建议长时间压力测试
    - 涉及安全、权限类修改，必须额外做安全审计
3. **可选扩展**
    - 可以再加一列：**推荐负责人技能标签**（例如：AMS专家 / SELinux / SystemUI / 性能功耗）
